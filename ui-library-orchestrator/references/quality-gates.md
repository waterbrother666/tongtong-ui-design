# 实施和浏览器质量门槛

根据改动风险调整检查深度，但不能仅凭源码检查就宣称页面完成。

## 修改前

- 阅读仓库指令并检查工作树，保留用户的无关改动。
- 找到真实路由、后端契约、加载/错误行为和权限边界。
- 检查现有布局、字体、CSS 变量、Tailwind 配置、图标、表单模式和原语系列。
- 记录包管理器和框架版本。
- 若需用户选择，先核对候选组件的官方具体页面，再检查项目专属 Markdown 草图确实画出方案差异、链接可打开且问题可直接回答；未选定前不改业务页面。
- 在官方来源中核对每个选中的外部组件。

## 安装后

- 检查所有新生成文件和依赖/锁文件差异。
- 确认 CLI 没有覆盖已经定制的本地原语。
- 确认导入路径使用目标项目的别名和组件目录。
- 删除不属于产品的 Demo 资产、文案、Mock 状态和样式。
- 不保留未使用的已安装组件或重复依赖。

## 功能验证

- 根据仓库实际配置运行 typecheck、lint、单元测试和 build。
- 启动真实开发服务，访问本次改动的真实路由。
- 验证主要成功路径，以及流程支持的加载、空、错误、禁用和危险操作状态。
- 验证后端数据映射和操作结果；能渲染一个 Mock 页面不等于已经接通后端。
- 检查浏览器控制台的错误和警告。

## 视觉和交互验证

- 至少检查一个窄视口和一个常规桌面视口；密集仪表盘再增加宽视口。
- 检查溢出、长标签、长 AI 输出、代码、附件、表格和本地化内容。
- 使用键盘导航所有控件，确认焦点可见且顺序合理。
- Dialog、Sheet、Menu 和 Popover 要验证焦点进入、必要的焦点限制、Escape、关闭和焦点返回。
- 悬停交互必须有触摸或键盘替代方式。
- 只有当目标项目支持深色模式时才验证深色模式。

## 动效验证

- 分别测试正常动效和 `prefers-reduced-motion`。
- 动效必须解释状态变化或层级，不得延误任务完成。
- 避免布局跳动、密集内容附近的重复自动播放和多个竞争特效。
- 检查不稳定 React key 或不必要重新挂载导致的动画重启。
- 多个动画项同时出现在列表或表格时，检查渲染性能。

## 完成报告

需说明：

1. 选中的组件库和具体组件。
2. 它们胜过其他选项的组件级原因。
3. 修改的依赖和文件。
4. 运行的命令/检查及其通过或失败结果。
5. 实际检查的浏览器路由、状态、视口、键盘行为和减少动画行为。
6. 仍存在的后端、浏览器、设计或兼容性边界。
